# 🔄 مراسلاتي 360° — نظام التقييم المتبادل الشامل
## Morasalaty & Samaa Group — 360-Degree Employee Feedback

نظام تقييم 360° لموظفي **مراسلاتي** و**سماء جروب**: تقييم الزملاء، تقييم المدير لفريقه، التقييم الإداري من الموارد البشرية، والتقييم الذاتي — مع لوحة تحليل ذكية وتقارير جاهزة لمدير النظام.
يعمل على **Vercel** (Serverless) مع قاعدة بيانات **Neon PostgreSQL**.

---

## 👥 الأدوار والصلاحيات

كل قرار صلاحية يمر عبر ملف واحد: [`lib/permissions.js`](lib/permissions.js) — ويُطبَّق في الخادم على كل طلب، والواجهة لا تستطيع تجاوزه. مغطى بالاختبارات في [`test/permissions.test.js`](test/permissions.test.js).

| الدور | ماذا يقيّم | يرى النتائج؟ |
|---|---|---|
| **موظف** | كل زملائه (360°) + نفسه | لا |
| **مدير إدارة** | مثل الموظف + موظفي إدارته (غير المديرين) | لا |
| **الموارد البشرية** | مثل الموظف + تقييم إداري لكل الموظفين | لا |
| **مدير النظام** | لا يقيّم ولا يُقيَّم | نعم — مجمّعة فقط + إدارة المستخدمين والدورات |

**قواعد السرية**
- بعد إرسال أي تقييم يُغلق نهائياً ويختفي الشخص من قائمة المقيِّم، ولا يمكن لأحد (حتى كاتبه) فتحه مرة أخرى.
- لا يرى أي موظف أو مدير أو موارد بشرية أي نتائج.
- مدير النظام يرى النتائج مجمّعة؛ تقييمات الزملاء لا تُظهر أبداً من الذي قيّم، والتعليقات تُعرض بترتيب عشوائي ثابت.

تُحدَّد الأدوار والإدارات من شاشة **«المستخدمون والصلاحيات»** (إضافة/تعديل/تعطيل مستخدم، كلمة مرور جديدة، مصفوفة الصلاحيات، وتنبيهات مثل «إدارة بدون مدير»).

## 📝 قوائم التقييم

1. **تقييم الزملاء (360°)** — 8 معايير مدمجة + نقاط القوة وفرص التطوير ([`data/modules.js`](data/modules.js)).
2. **تقييم المدير** — SLA، التعامل مع الذروة والأزمات، جودة التوثيق، العمل الجماعي.
3. **التقييم الإداري (الموارد البشرية)** — الالتزام بثقافة الشركة، المرونة في الطوارئ، الاستجابة والجاهزية.
4. **قيّم نفسك** (آخر قائمة) — إدارة الوقت وضغط العمل، التعلم المستمر، الاستباقية + سؤال مفتوح عن المبادرة، وسؤال استطلاع «نكست ون» مرة واحدة لكل موظف.

الحفظ تلقائي كمسودة، وحالة الحفظ المعروضة حقيقية (تظهر «لم يتم الحفظ» عند فشل الاتصال).

## 📊 التحليلات (مدير النظام فقط)

- **لوحة التحليل**: مؤشرات رئيسية، **ملاحظات تلقائية** (الأعلى/الأقل، أقوى وأضعف معيار، فجوة التقييم الذاتي، اختلاف المدير مع الزملاء، موثوقية النتائج…)، وكل قسم فيه قائمة لاختيار البيانات المعروضة (المقياس، المصدر، الموظف، التجميع) مع عرض كمخطط أو جدول وتصدير CSV.
- **التقارير الثابتة**: تقييم الموظف من زملائه · إجمالي تقييم الموظف · تفاصيل تقييم موظف · المتوسط النهائي على مستوى الشركة · فجوة التقييم الذاتي · مقارنة الإدارات · نقاط القوة وفرص التطوير · استطلاع نكست ون.
- **الدرجة النهائية** = متوسط موزون (افتراضياً: الزملاء 40% · المدير 35% · الموارد البشرية 25%)، الأوزان قابلة للتعديل من اللوحة.
- **متابعة المشاركة**: من أرسل كم تقييماً (بدون أي محتوى).
- **دورات التقييم**: ابدأ دورة جديدة (شهرية/ربع سنوية) وتبقى نتائج الدورات السابقة متاحة.

> لا توجد أي درجات افتراضية أو مصطنعة: عند غياب البيانات يظهر «—».

## 🚀 النشر على Vercel (مهم — بالترتيب)

1. **غيّر كلمة مرور قاعدة البيانات في Neon** — كلمة المرور القديمة كانت منشورة في المستودع العام.
2. في Vercel → Project → Settings → **Environment Variables** أضف:
   - `DATABASE_URL` = رابط الاتصال الجديد من Neon.
   - (اختياري لأول دخول) `ADMIN_BOOTSTRAP_EMAIL` و `ADMIN_BOOTSTRAP_PASSWORD` (12 حرفاً على الأقل). تعمل مرة واحدة فقط لحساب مدير نظام لم يحصل بعد على كلمة مرور جديدة، ويمكن حذفها بعد الدخول.
3. انشر (Deploy). عند أول طلب يحدّث النظام قاعدة البيانات تلقائياً — **إضافات فقط، لا يُحذف أي شيء**، وتُنقل تقييمات المدير/الموارد البشرية/الذاتي القديمة إلى الجدول الجديد.
4. ادخل كمدير نظام ← «المستخدمون والصلاحيات»: راجع الأدوار والإدارات، ثم **«كلمات مرور جديدة للجميع»** ونزّل القائمة ووزّعها. كلمات المرور القديمة (mora123 وغيرها) **لم تعد تعمل**.

بديل للخطوة 2/4 من جهازك: `DATABASE_URL="..." npm run set-password -- mahmoud@tieapps.com`

## 🗂️ هيكل المشروع

```
api/index.js          الـ API (مسار واحد لكل العمليات)
lib/permissions.js    الأدوار والصلاحيات (الخادم + المتصفح)
lib/questions.js      أسئلة القوائم الأربع والتحقق من الإجابات
lib/schema.js         إنشاء/تحديث قاعدة البيانات (إضافات فقط) + نقل البيانات القديمة
lib/analytics.js      تجميع النتائج (بدون هوية المقيِّم)
lib/passwords.js      تشفير كلمات المرور (scrypt) والجلسات
assets/               الواجهة (HTML/CSS/JS بدون مكتبات خارجية)
data/                 أسئلة الزملاء والموظفين الافتراضيين (بدون كلمات مرور)
scripts/              init_db / set_password / بيئة محلية
test/                 الاختبارات
```

## 🔐 الأمان

- لا توجد كلمات مرور أو بيانات اتصال في الكود.
- كلمات المرور مشفرة بـ scrypt مع salt، والجلسات مخزنة كـ hash وتنتهي بعد 72 ساعة.
- قفل مؤقت بعد 8 محاولات دخول فاشلة خلال 15 دقيقة.
- سياسة Content-Security-Policy صارمة، وكل النصوص تُعرض بعد escaping.
